# 做出一整套輪播

使用者這次的要求：$ARGUMENTS

完整流程在 `${CLAUDE_PLUGIN_ROOT}/references/carousel.md`，寫字規則在 `${CLAUDE_PLUGIN_ROOT}/references/writing-rules.md`，先讀這兩份再動手。下面是執行順序與不能省的檢查點。

## 0. 分辨這次要做到哪

| 使用者說的 | 做到哪裡 |
|---|---|
| 「把 X 做成一套輪播」「幫我做圖文」 | 規劃、文案、成圖、貼文全部做完，一次交整套 |
| 「先給我文案」「先看大綱」 | 停在逐頁文字，不畫圖 |
| 「改第 3 張」「第 2 張的字換成……」 | 只改那一頁的 spec 與圖，其他不動 |
| 「換個封面」 | 只重做封面，可以給 2 到 3 個標題方向讓他選 |

主題明確就直接做，不逐項確認。只有缺少會改變內容的關鍵資料才問，而且一次問完。

## 1. 讀品牌、查工具

1. 依 `references/brand.md` 讀品牌設定。沒有設定檔照常做，交付時提醒一句。
2. 跑 `bash "${CLAUDE_PLUGIN_ROOT}/scripts/check_tools.sh" --for carousel`，把結果列給使用者（有什麼、缺什麼、怎麼裝）。缺 Python、Pillow 或字型時不停下來：先完成第 2 到 4 步，圖片那段改成「規格檔已寫好，裝好工具後說一聲我就畫」。

## 2. 規劃頁序

先決定：讀者遇到什麼、看完得到什麼、最後做什麼。再排頁序，一頁推進一件事，張數由內容決定。封面只搶一個主訊息，手機縮圖一秒看懂。CTA 頁只放一個動作，入口沒確認過就標成提案。

## 3. 寫逐頁文字與規格檔

圖上文字用繁體中文，主標短，行尾不放標點。每頁寫成 JSON，格式照 `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/render_carousel.py" --example`。顏色與浮水印從品牌設定帶入。

存到工作資料夾的 `ai-staff-output/<今天日期>_<主題短名>/spec.json`（品牌設定另有指定輸出位置時照它）。

## 4. 畫圖、逐張看、修

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/render_carousel.py" <spec.json>
```

腳本會回報哪一頁放不下。接著用讀圖工具逐張打開大圖看：文字有沒有被截或擠、斷行自不自然、主次清不清楚、浮水印有沒有壓到字。再看 `00_overview.png` 的整套節奏。有問題就改 spec 再畫，只改一頁用 `--only N`。最多修三輪，仍有問題就如實說哪一頁要人工調。

不要只看檔名就說「做好了」。沒有實際打開看過的圖不能說已檢查。

## 5. 寫貼文

寫 IG 版 caption：前兩行決定會不會展開，先講讀者會得到什麼；結尾的 CTA 和圖上一致；hashtag 放最後、半形、少量貼題。品牌設定有 FB 或 Threads 時另寫對應版本（Threads 不放 hashtag）。寫完跑 `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/text_check.py"` 檢查，「要改」的一定改。

## 6. 交付

- 成品資料夾路徑、總覽圖、逐張檔名。
- 完整貼文放在程式碼區塊，直接可複製。
- 標出提案與待確認的地方（例如 CTA 入口還沒建）。
- 一句：想改哪一張跟我說第幾張，或直接貼要改的句子。

成圖不等於發布。要排程另外用 `/ai-staff:schedule-post`，要做留言送禮用 `/ai-staff:comment-gift`，這裡不自動接下去。
