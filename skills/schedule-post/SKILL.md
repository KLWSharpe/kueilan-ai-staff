# 把成品排進 Meta 後台

使用者這次的要求：$ARGUMENTS

完整做法在 `${CLAUDE_PLUGIN_ROOT}/references/scheduling.md`，先讀完。這個指令的重點不是怎麼點，是怎麼不點錯：排程、立即發佈、加強推廣在畫面上只差幾十個像素。

## 1. 收齊五件事

從使用者的話、品牌設定（`references/brand.md`）與成品資料夾取得：

1. 排到哪個粉專、哪個 IG 帳號。
2. 圖片或影片檔案與順序（檔名 `01_`、`02_`… 零填補；`ls | sort` 的順序就是上傳順序）。
3. 已確認的貼文文字，逐字用，不再改。
4. 日期、時間、時區。
5. FB 和 IG 要不要不同文案（沒說就一樣）。

缺的一次問完。使用者給的時間就照抄，不推銷更好的時段。

## 2. 查工具與撞期

看目前對話有沒有能操作瀏覽器的工具（Claude in Chrome、內建瀏覽器或電腦控制）。

- 有：打開 Meta Business Suite 的「已排定」清單，讀出同一天已有的排程，記下來。
- 沒有：明說這次沒辦法替他操作後台，後面會把核對表與操作步驟整理成清單給他自己點。

## 3. 核對表，等 OK

把這張表整理給使用者：

| 項目 | 內容 |
|---|---|
| 帳號 | 粉專名、IG 帳號名 |
| 平台 | FB、IG 或兩者 |
| 時間 | YYYY-MM-DD HH:MM（時區） |
| 圖片 | 依序列出檔名，共幾張 |
| 文案 | 完整貼文（程式碼區塊） |
| 撞期 | 同一天已有的排程，或「沒有」 |

結尾說：「確認沒問題請回我 OK，我才會排。」沒有收到 OK 不進後台。使用者改了任何一項，更新表再問一次。

## 4. 進後台排（收到 OK 之後）

照 `references/scheduling.md` 第二步做。不能省的檢查點：

- 先截圖確認畫面上的帳號是核對表上的帳號。
- 圖片一次多選上傳；雲端同步資料夾的檔案先複製到本機暫存資料夾。
- 送出前截圖確認日期、時間、張數、首尾兩張。
- 讀出按鈕文字確認是「排程」或「排定」，再獨立一次呼叫點下去。
- 不碰「立即發佈」「加強推廣」「在廣告管理員中建立廣告」「刪除貼文」。
- 同一顆按鈕連續失敗兩次就停下來回報，不重試。

## 5. 讀回對帳

重新打開「已排定」清單，讀出標題、帳號、時間，和核對表逐列比對，做成表格回報（FB 與 IG 各一列）。多圖輪播另外打開已排定貼文預覽，確認張數與首尾兩張。看一眼「已發佈」最上面幾筆，確認沒有東西被提早發出去。

對不上就回去修，修完重讀。只有這張表都「符合」才說排好了。

## 交付

- 對帳表。
- 後台「已排定」的畫面截圖（有的話）。
- 這次沒做或沒驗到的事，例如沒有瀏覽器工具、圖序無法從介面確認。

誤發或誤刪時立刻告訴使用者，不自作主張補救；刪除一律選「移到垃圾桶」。
