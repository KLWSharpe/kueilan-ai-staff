# 留言送禮，自動送到私訊

使用者這次的要求：$ARGUMENTS

完整做法在 `${CLAUDE_PLUGIN_ROOT}/references/manychat.md`，先讀完。ManyChat 的介面與方案會變，每一步以當下畫面為準，不把這份文件的步驟當保證。

## 1. 先定規格

從使用者的話與品牌設定（`references/brand.md`）整理這張表，缺的一次問完：

| 項目 | 內容 |
|---|---|
| 平台 | IG、FB 或兩者 |
| 貼文 | 已發布（連結）或未發布 |
| 關鍵字 | 主關鍵字，加繁簡變體與常見錯字 |
| 贈品 | 實際可打開的連結或檔案 |
| 追蹤門檻 | IG：要不要先檢查追蹤。FB：只能提醒，不能驗證 |
| Email | 要不要收、用途是什麼 |
| 結尾 | 送完結束，或接哪個商品入口 |
| 終點 | 草稿（預設）或使用者明確說要啟用 |

沒有真實贈品就不能上線，不填假連結。使用者說「不追蹤」只拿掉追蹤，「不收 Email」只拿掉 Email，沒提就沿用品牌設定的預設。

## 2. 寫文案

- 私訊：一則氣泡說完一件事，自然的單段文字，不每句換行、不堆 emoji。還沒通過門檻不能說「已經給你了」。
- 收 Email 的句子：請求、交付方式、用途寫在同一段，用途要真實。
- 公開回覆：至少 5 句不重複，提醒看私訊，口吻跟品牌一致。
- 關鍵字清單：主關鍵字、簡體寫法、常見錯字、加標點版本，去重後列成一行。

把規格表與全部文案給使用者看，請他確認或改。

## 3. 建置（有瀏覽器工具且 ManyChat 已登入時）

照 `references/manychat.md` 的建置步驟：先截圖確認帳號，找同贈品舊流程，相容才沿用，否則複製再改；改名；設觸發、門檻、Email、交付、結尾；存檔後重新載入逐欄讀回。

預設停在 STOPPED（草稿）。把流程連結給使用者，說「你檢查過說啟用我才啟用」。使用者明確說啟用後才切 LIVE，切完再讀回狀態。

沒有瀏覽器工具或沒登入：把規格、文案、關鍵字清單與步驟整理成一份清單交給使用者自己設，明說這次沒有實際建在帳號裡。

## 4. 交付

- 規格表、私訊文案、公開回覆、關鍵字清單。
- 流程連結與目前狀態：已儲存、草稿或已啟用。
- 還沒做的事：例如貼文發布後要把觸發從「所有貼文」切到指定貼文、真人端到端測試還沒做。

只有實際用另一個帳號留言並收到私訊，才能說「真人收到」。業配貼文不混自家商品 CTA。
