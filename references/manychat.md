# 留言送禮（ManyChat）流程

`/ai-staff:comment-gift` 用這份。ManyChat 的介面、方案與平台政策會變，每次以當下畫面和官方文件為準，不把舊步驟當保證。

## 先定規格，再動帳號

| 項目 | 要確定的內容 |
|---|---|
| 平台 | IG、FB 或兩者。沒說就依品牌設定；都沒有才問 |
| 貼文 | 已發布（綁指定貼文）或未發布（先用所有貼文加本篇專屬關鍵字，發布後再切） |
| 關鍵字 | 主關鍵字加繁簡變體、常見錯字。先查帳號內有沒有別的流程用同一個字 |
| 贈品 | 實際存在、可打開的連結或檔案。沒有真的贈品不能上線，不填假連結 |
| 追蹤門檻 | IG 可用真實追蹤判斷；FB 只能提醒，不能宣稱已驗證追蹤。品牌設定有預設就沿用，使用者說「不追蹤」只取消追蹤 |
| Email | 要不要收、用途是什麼、已有 Email 的人不重問。使用者說「不收 Email」只取消 Email |
| 結尾 | 送完就結束，或接一個商品入口。業配不混自家 CTA |
| 終點 | 草稿（預設）或直接上線。沒有使用者明確說「啟用」，一律停在草稿 |

把這張表整理給使用者看，缺的一次問完。

## 文案

### 私訊

一則氣泡說完一件事，自然的單段文字，手機會自己換行。不每句換行、不固定字數、不堆 emoji。例：

```
這份整理給你，點下面就能看，也可以存起來慢慢讀。
```

要收 Email 時把請求、交付方式、用途寫在同一段，用途要真實：

```
請留下你的 Email，我會把這份整理寄給你，之後有新的教學也會從這裡通知你。
```

還沒通過門檻不能說「已經給你了」；不會寄信就不寫「寄到信箱」。

### 公開回覆

每個留言觸發準備至少 5 句不重複的公開回覆，提醒對方看私訊，口吻跟品牌一致。例：「私訊傳給你了，看一下收件匣」「已經送到你的私訊，沒看到的話檢查一下訊息請求」。

### 關鍵字變體

主關鍵字之外列簡體寫法、常見錯字、加標點的版本，全部去重後列成一行方便貼進後台。

## 建置（有瀏覽器工具且 ManyChat 已登入時）

1. 先截圖確認登入的是哪個 ManyChat 帳號與哪個 IG／FB。
2. 在 Automation 搜尋同贈品的舊流程；目的、門檻、交付相容才沿用，否則複製一份再改，不動原流程。
3. 新建或複製後立刻改名，格式：`日期或待上架_平台_留言「關鍵字」_送_贈品名`。
4. 依規格設觸發、門檻、Email、交付、結尾。刪掉的關卡連同按鈕與催填文字一起清乾淨。
5. 存檔後重新載入，逐欄讀回文字、連結、條件、關鍵字清單、狀態。
6. 預設維持 STOPPED（草稿）。把流程連結交給使用者檢查，說「你看過說啟用我才啟用」。

沒有瀏覽器工具或沒登入時：把規格、文案、關鍵字清單與建置步驟交給使用者自己設，明說這次沒有實際建在帳號裡。

## 驗收

分清楚四種狀態：已儲存、已啟用、已排程、真人已收到。只有實際測過（用另一個帳號留言並收到私訊）才能說真人收到。
